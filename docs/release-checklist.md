# GitHub 发布准备与验收清单

更新：2026-09-25。目标：AURORA 前后端及 Agent 编排开源，用户在本机自行配置模型 API Key。**当前结论：可以继续开发与预览，尚不具备独立产品发行条件。** 本文不授权提交、推送或创建公开仓库。

## 阶段 A：已开始的质量检查

- [x] 对照原实现审查聊天、恢复、附件、存储和项目导航；为确认缺陷添加回归测试。
- [x] 扫描当前前端依赖并升级存在已知告警的测试工具。
- [x] 增加候选源码检查脚本：报告路径和规则，不打印匹配到的密钥。
- [x] 准备 Windows/Linux 的 GitHub Actions 前端检查、贡献说明与 PR 模板。
- [ ] 在 GitHub 实际运行 CI。当前只有本机验证，不能标注云端 CI 已通过。

完成证据见 `pre-release-audit-2026-09-25.md`。自动测试不替代下面的发行验收。

## 阶段 B：独立后端与安全修复

- [x] 第一批：独立静态/HTTP 运行入口、本机会话、空白状态和安全文本文件接口已实现；详见 `runtime-foundation.md`。
- [ ] 下一批：原研究引擎与必要插件迁入该运行边界并完成真实协议验收。第一批不等于整个后端已经独立。
- [ ] 建立独立 runtime 源码/构建边界，列出实际需要的插件、Skills 和依赖。保留成熟研究能力，不整包复制旧开发工作区。
- [ ] 修复旧 HTTP 入口写死关闭认证的问题；本机实例认证、允许 Origin、预检及错误路径有明确测试。默认只绑定回环地址。
- [ ] 所有文件入口验证完整目标路径和真实父目录，覆盖上传文件名、Windows 路径、目录穿越与符号链接；使用临时目录测试，不对现有研究文件做攻击测试。
- [ ] 重新审查发行依赖的告警及实际可达性，升级/移除受影响依赖并保持补丁兼容。旧工程依赖扫描结果不能直接作为发行包的漏洞数量。
- [ ] 初始化独立用户状态目录，不读取作者旧环境、默认模型账户、auth profile 或研究历史。
- [ ] runtime 同源提供静态前端、HTTP 和 WebSocket；不依赖 Vite 开发服务器。验收启动、关闭、端口冲突、冷启动与升级。

退出条件：在没有相邻 ANLYST 目录的新环境，源码安装可启动到配置界面；无个人数据和旧配置依赖。此阶段先验证运行边界，再接入用户密钥。

## 阶段 C：用户自带模型完整流程

- [ ] 复用原模型管理的连接测试、凭据管理和配置更新，接入 AURORA 的设置界面。
- [ ] 用户配置协议、Base URL、模型 ID 与 API Key；可更新/删除，保存后能够重启恢复。
- [ ] 主模型和所有辅助角色均使用用户配置；角色缺省继承用户主模型，无凭据则明确待配置，不采用作者供应商兜底。
- [ ] 模型 Key 由本机后端管理，不进入静态构建、前端持久化、URL、日志或导出。连接测试只在用户操作时调用模型。
- [ ] 验收无 Key、错误 Key、正确 Key、替换/删除 Key、服务不可达、模型不支持工具调用、重启和运行中切换的行为。
- [ ] 用独立测试状态验证真实研究的任务、工具、附件、来源、停止、历史恢复和辅助调用；记录实际模型与能力，避免将夹具结果写成在线验证。

退出条件：用户只用自己的服务与凭据完成一次研究；未配置功能清晰说明，作者环境不可作为隐含依赖。

## 阶段 D：首版范围与文档

- [ ] 按六个原定页面逐项确认真实能力：研究、项目、文件、报告、自选、提醒。当前文件/报告管理、自选与提醒仍有未接入操作。
- [ ] 接通会话重命名/归档的持久化，或在首版明确限制；当前真实会话的这两项更改仍会在刷新后恢复。
- [ ] 完成文件来源阅读、长历史分页、错误/停止终态恢复和复杂结果渲染的约定范围；未完成项明列，不以演示效果替代。
- [ ] 首版优先验收 Windows；Linux/macOS 的支持状态以实际安装验收为准，前端 CI 通过不等于完整后端跨平台可用。
- [ ] README 改为从零安装、模型配置、运行、升级、卸载与故障排查；提供空白配置示例，不提供真实 Key。
- [ ] 保留来源、许可证和归属；确认 AURORA 根许可证及衍生代码发布权限。根 LICENSE 当前尚未确定，不能只靠第三方许可证文件完成授权。

## 阶段 E：候选仓库与发布

- [ ] 确认用户 GitHub 账号下的仓库名称、许可方案、首版标签和说明；此时再核验同名仓库与远端状态。
- [ ] 按候选文件清单审阅源码、文档、字体/图标和测试夹具，排除个人配置、日志、研究内容及含私人数据的截图。
- [ ] 运行 `pnpm check:source`、`pnpm test:release`、类型/静态/单元/浏览器/构建检查及依赖扫描。该源码脚本只匹配有限规则，不覆盖完整 Git 历史和二进制内容。
- [ ] 发布前再使用完整密钥扫描工具检查 Git 历史与实际发行产物；首次提交前后均检查。`.gitignore` 不会清除已经提交的数据。
- [ ] 用实际候选源码包在干净目录安装、启动并完成 BYOK 研究；安装包同样验收，不把本机开发目录的成功当作下载验收。
- [ ] 展示待发布内容、已知限制和验证结果，取得发布指令后再创建/推送公开仓库或 Release。

## 当前仓库基础设施

- `scripts/check-public-source.mjs`：候选源码卫生检查。
- `scripts/check-public-source.test.mjs`：检查器行为与不回显秘密的测试。
- `.github/workflows/check.yml`：仅前端与协议夹具检查，无模型凭据、部署或发布步骤。
- `CONTRIBUTING.md`、`.github/pull_request_template.md`：贡献及验证说明。

目前没有为开源动作创建提交、远端仓库、标签或 Release。下一实施检查点为阶段 B，完成后再做阶段 C；保留用户要求的串行验收。
