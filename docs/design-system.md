## 标识可读性修正

日间 AURORA 使用 opsz=6 的光学字号参数、650 字重（侧栏 700）与深绿 #124F36，保留衬线风格并避免细笔画消失。夜间黑金配色保留。NVIDIA SVG 显式填充 #76B900、使用白底；AMD 使用 #D71920 红底和白色标志。标识通过共享 CompanyLogo 按 Ticker 呈现，已有本地会话无需迁移。

## 导航与设置层级

项目和聊天分别设置标题。项目名称 15px/550，以文件夹图标识别；其会话缩进、竖线分组，Logo 保持 32px。置顶会话仍留在所属项目，独立聊天不重复展示项目内容。空项目也能显示和创建研究。

最新密度调整：去掉“全部研究”标签；项目与聊天标题均为15px/600，聊天分隔区上方和内部留白从22/20px收至10/10px。聊天历史仅展示文字，项目里的公司标识保留。

左下角为轻量弹出菜单，使用单列图标行和分隔线；设置单独打开 780×500 分类面板。桌面左分类右内容，手机顶部分类；常规只有主题与布局，连接与登录单独一页，演示调试独立一页。内容多时仅当前内容区滚动，避免整个设置面板成为混杂的长列表。

## 选择浮层与主题动效

研究模式和模型选择共享 SelectionMenu：主题边框/阴影、图标、描述、选中勾选，以及130ms轻量进入动画。浮层优先向输入框上方展开，根据可见视口翻转与限高，支持键盘和焦点返回；不会提交输入表单。演示模型仍明确为演示，实际模型使用后端名称和provider，已发起的实时会话保留锁定。

主题切换使用 View Transitions 的旧/新页面快照，从点击位置以620ms圆形剪裁扩散到全屏；图标配合420ms旋转。切换不重建研究页、不清空草稿；连续切换以最后一次选择为准。减少动效时立即切换，不支持API时使用短淡入回退。实现依据：[Chrome 同文档 View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)。

## 连续对话与自适应输入

用户消息按内容定宽并右对齐，最大宽度为正文82%与760px中的较小值；移动端允许至96%，长单词/链接换行。正文与输入区沿同一阅读宽度对齐，收紧消息间的无效留白。

桌面输入框默认约56px高，附件、单行文字、模式/模型与发送在同一行。长文本、换行、附件或窄栏时展开为上下两层；textarea自动测量高度，最多180px/视口高度25%，超过后内部滚动。测量基于紧凑布局的可用宽度，避免展开/收起反复抖动。清空、切会话和栏宽变化都会重算。

手机与窄栏保留较低的两层布局，完整显示模式、模型及停止按钮。滚到最新按钮锚定输入区上缘，不使用旧固定182px/178px底部偏移。

日间用户消息用深绿 #176744 底、白字 #FFFFFF，提升用户问题与白底研究回答的角色区分；附件文字使用浅色以维持可读性。气泡依然按内容定宽，不恢复大横条。
