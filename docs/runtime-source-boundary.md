## 为什么不直接复制原插件入口

已检查 `extensions/fin-core/index.ts` 和 `http-files.ts`：研究能力与旧网页、连接器、用户管理及多渠道依赖混合注册，并跨目录引用核心内部实现。仅把插件文件移动到 AURORA 不能形成可独立安装的后端。

本轮从 `src/gateway/server.ts` 与 `extensions/fin-core/index.ts` 追踪静态引用，得到超过 2,500 个源文件的保守上界，包含类型引用、原插件 SDK 导出和遗留 UI，不等于发行版实际必须加载的文件数。动态路径和构建生成资源仍需另行检查。原始清单保存在忽略目录 `.runtime/runtime-source-inventory.json`；分析只读取源码，没有读取个人环境、密钥或会话。

## 下一批的可验收结果

- 明确的研究引擎入口与依赖清单；源码和构建不引用相邻 ANLYST 或其 node_modules。
- 原任务、工具、历史、停止与事件隔离测试迁入并通过；新旧运行的协议差异显式列出。
- 只提供当前产品所需的方法；旧 HTTP handlers 不挂在新实例上，避免重新引入调试认证绕过。
- 引擎文件操作与 HTTP 文件操作共享同一状态和路径边界；不回退到旧个人工作区。
- 最终依赖重新锁定、扫描并核实适用性。之前旧工程的告警数量不能直接套到新运行包，也不能因为新的 HTTP 基础没有第三方依赖就宣称引擎告警已消除。

完整独立研究和 BYOK 验收通过之前，README 应继续写明“研究引擎尚未迁入”。
