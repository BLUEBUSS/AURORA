# AURORA 开源与用户自带模型方案

日期：2026-09-25。状态：用户已确认方向，首轮缺陷修复与发布检查基础设施已完成；独立 runtime 和 BYOK 尚待实施。具体证据见 `pre-release-audit-2026-09-25.md`，执行清单见 `release-checklist.md`。本文取代上一轮讨论中的闭源 Agent 编排和闭源后端安装包方案。

## 已确认的产品边界

- 前端、产品所需后端和 Agent 编排均按开源准备。保留 AURORA 独立工程边界，复用已验证的现有实现，不直接发布 ANLYST 整个开发目录或个人运行环境。
- 程序在用户本机运行；用户自行接入模型服务并承担调用费用。模型 API 可能是远程服务，本机运行程序不等于模型推理完全离线。
- 作者的模型额度、数据服务账号、密钥、个人配置、历史会话、研究文件和运行日志不属于交付内容。
- 开源范围中的第三方及团队衍生代码须核对来源和发布权限，保留许可证与归属；AURORA 的根许可证在发布准备时明确，不因本方案自动变更既有代码授权。

## 用户首次使用流程

1. 安装独立 AURORA，启动本机服务与界面；无需存在相邻 ANLYST 目录，也不读取开发者的旧配置目录。
2. 进入模型设置，选择协议/服务商，填写服务地址、模型 ID 和自己的 API Key。
3. 明确点击测试连接并查看结果。测试模型响应可能产生少量费用，不在用户填写字段或启动软件时自动发起付费推理。
4. 保存后开始真实研究。没有有效配置时显示“配置模型”入口，可主动选择演示；不借用作者的默认模型或密钥兜底。
5. 主模型及辅助模型（例如路由、摘要、标题、上下文压缩）均解析为用户配置。可显式选择辅助模型，但缺失配置时不能回落作者环境。

## 配置与数据边界

- 密钥交给本机后端保管；保存方式应使用本机凭据存储，或限制访问权限的用户配置文件。具体持久化方案实施时验证，不宣称现有版本已具备。
- 不把模型密钥放入前端构建变量（含 VITE_*）、前端静态文件、localStorage、URL 或默认示例。配置读取只返回是否已配置和掩码，不返回原始密钥。
- 本机后端初始化独立状态目录和实例认证信息，默认绑定回环地址；模型设置接口需要本机身份校验与 Origin 校验。
- 未配置付费数据源时，明确标注相应能力不可用或待配置，不转用作者凭据，也不以演示数据冒充真实数据。
- 日志、错误、诊断导出和模型连接测试结果需脱敏。安装包、源码包、测试夹具、截图及 CI 产物均纳入发布检查。

## 当前差距

- 已核对原版 ModelManagerModal 与 model-router 源码：已有连接测试、凭据保存/删除及模型配置更新流程，可以迁移复用；这只是源码能力确认，尚未在 AURORA 进行用户自带凭据验收。
- AURORA 的真实研究主链路已验证，但当前模型来源仍是既有后端的 models.list，不能视为已经实现用户自带 API Key 的首次配置。
- scripts/start-local.ps1 默认调用 start-backend.ps1，后者依赖旧 ANLYST 构建、个人运行配置和扩展路径；需替换为发行版独立启动方式。
- 当前 Vite 开发代理不等于正式本机服务；发行版必须实际提供前端静态页面及 HTTP/WS 连接。
- 文件/报告管理、自选与提醒的完整后端操作尚未全部接入，应与发布范围明确对齐。

## 串行实施检查点

1. 确定产品必需的源码与依赖清单，准备无个人数据的后端默认配置，核对授权与第三方通知。
2. 接入首次模型配置、连接测试和本机凭据保存，覆盖主模型与所有辅助模型。保留当前开发环境供回归，不覆盖已有用户配置。
3. 形成独立源码启动和安装/升级路径，移除对作者机器、旧目录及私有默认服务的依赖。
4. 在干净目录与独立状态目录验收：无 Key 时提示配置；正确 Key 可研究；错误 Key 可修正；重启后可恢复；更换/清除凭据有效；停止、流式、文件与历史行为保持正常。
5. 检查源码、Git 历史及实际发行产物中的秘密和个人数据，更新 README、许可证和功能范围说明，再准备用户可审阅的 GitHub 发布内容。

单元测试和协议夹具只证明相应代码行为；“用户自己接 API 后可用”必须通过独立安装与真实模型验证后再宣称。本次方向更新未执行模型调用、提交、推送或公开发布。
