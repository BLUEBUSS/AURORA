# 独立本机服务：第一批实施

这是第一批历史记录。2026-09-26 已迁入独立研究主链路和用户模型配置，最新结果见 `engine-byok-acceptance.md`；下面“引擎未接入”等描述仅指当时状态。

阶段：发布清单 B 的运行入口与文件边界。**这是可运行的服务基础，不是已经迁入全部 Agent 的独立研究后端。** 原 ANLYST 开发目录保持不变，兼容入口仍可用于已有研究联调。

## 已实现

- `runtime/` 为独立 TypeScript 源码，编译为 `dist-runtime/main.mjs`；当前服务运行只依赖 Node 内置模块，不导入旧源码、旧 node_modules 或个人配置。
- `pnpm build` 同时生成前端和本机服务；`pnpm start` 同源提供静态页面和本机 API，默认监听 `127.0.0.1:5174`。它不启动 Vite。
- 默认状态位于当前用户的 Aurora 应用数据目录。可用 `--state-dir` 或 `AURORA_STATE_DIR` 指定独立目录；不会读取 OpenClaw/Antlyst 状态和模型环境变量。
- 通过同源页面建立短期 HttpOnly / SameSite=Strict 会话。文件与 bootstrap 接口要求会话；修改请求还要求精确 Origin；Host 和回环连接也会校验。响应不提供 Gateway 管理 token。
- 文件接口复用现有前端契约，校验完整路径及现有父目录，拒绝路径穿越、Windows 驱动器/设备名/ADS、控制字符与符号链接。上传只接收有界 UTF-8 文本，并生成唯一文件名避免覆盖。
- 上传、列表、预览和下载实际读写独立工作区；预览按纯文本和 sandbox 响应，不能当作同源可执行 HTML 使用。
- 启动失败不会覆盖损坏的实例文件；端口冲突不会停止其他进程。重启保留本机身份和文件，旧会话 cookie 失效。

## 本批启动与测试

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

可选参数：

```sh
pnpm start --port 5175 --state-dir .aurora-state
```

目前页面仍可主动使用演示；真实研究入口会明确报告研究引擎尚未接入，不生成模拟的“已连接”状态。需要原后端联调时仍使用已有开发兼容脚本，两种入口不要占用同一端口。

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm test:runtime
pnpm build
pnpm test:e2e
```

新服务测试使用临时目录，覆盖真实 HTTP 会话、文件读写、过期/退出/重启、跨 Origin、伪造 Host、目录穿越、符号链接和端口冲突；不对个人研究工作区做破坏性测试。

## 本批验收结果

- 类型检查、静态检查、前后端构建通过；322 项前端/消息内核单测、31 项本机服务测试、33 项浏览器回归和 4 项发布检查器测试通过。
- 浏览器用编译后的真实页面访问本机服务，没有 mock 本机 API；已验证 HttpOnly cookie、真实上传/读回、刷新后文件保留、跨 Origin 拒绝及非法文件名拒绝。
- 单独复制 `dist/` 和 `dist-runtime/` 到没有源码、node_modules、旧后端的目录，仅使用 Node 启动：页面 200、未认证 bootstrap 401、建立会话 200、上传 200、读回内容一致。测试进程已停止。
- 当前 AURORA 依赖扫描没有已知告警；这不覆盖尚未迁入的研究引擎依赖。旧后端仍为原 HEAD，未改配置或研究数据。

## 信任边界与剩余工作

这是一人一实例的本机应用。网页跨站访问由服务端校验阻止；同一操作系统用户下能够伪造 HTTP 头、读写状态目录或修改程序的本地进程仍属于受信任宿主边界，不声称可以对抗宿主管理员或任意本地恶意进程。文件检查也不宣称提供对抗任意宿主文件系统竞态的隔离沙箱。

当前未监听原 Gateway 的管理协议，WS 研究入口返回未就绪；没有默认模型、作者密钥或自动模型调用。BYOK 和研究引擎接入仍待下一批完成。旧 HTTP 文件服务的调试认证绕过未在旧工程中修改；它不会被新服务转发或暴露。只有原研究能力正式接入新边界，并经过端到端验收后，才能将整个阶段 B 标为完成。
