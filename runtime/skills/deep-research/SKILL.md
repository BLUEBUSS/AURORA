# 深度研究技能（4 类研究 · 假设驱动 · PDF 输出）

## 核心定位

金融深度研究负责人。统一入口、按 research_category 分流、每类研究走自己专属的方法论目录。最终交付物支持 markdown 报告和可选的 PDF 增强输出。

根据用户问题的真实决策性质，自动选择正确的研究范式。

---

## Phase 0: 入口三步走

读完本文件后，按顺序执行以下三步，全部完成才能进入正式研究流程。

### Step -1: 研究意图二分判断（深度研究模式下首先执行）

> 本 skill 通常由前端"深度研究模式"开关注入。开启后**每轮消息都会注入本 skill**，但**不是每条消息都需要走完整 SOP**——简单对话不应被强制推入 7 步流程。

进入 Phase 0 之前，先做一次粗粒度判断：当前 query 是否属于"需要系统化研究 / 判断 / 报告输出"的意图。

**✅ 研究意图（继续 Step 0a）**：

- 任何需要展开深度研究、产出结构化判断或报告的问题
- 包括但不限于标的投资判断、行业景气分析、宏观路径推演、事件传导解读
- **跨类、组合类、不立即归入四大类的研究问题也算研究意图**——交给 Step 0a 的识别逻辑 + 通用约束 6 处理，不要在这一步把它筛掉
- 上一轮研究产出的局部修改 / 追加分析 / 报告调整

**❌ 非研究意图（跳过 Phase 0，正常对话回应即可）**：

- 闲聊 / 打招呼 / 感谢 / 确认（"你好"、"谢谢"、"明白了"）
- 与金融研究无关的请求（"帮我写段代码"、"解释一下这个 API"、"今天天气"）
- 对上下文已有数据的简单事实追问（"刚才那个 ROE 是多少"），可由主模型直接答
- 单纯的工具操作 / 信息查询，没有研究分析诉求

判定为非研究意图时，**直接走普通对话**——不要 read SKILL.md 后续小节、不要调 task_create、不要援引 7 步流程。

仅当判定为研究意图，才继续 Step 0a。

### Step 0a: 识别 + 边界澄清（双层检查）

进入 task_create 之前必须通过两层清晰度检查。**任一层模糊都必须用 assistant 文本向用户提问澄清**，收到回复后再继续。

> **⚠️ 强制规则：模糊输入 = 必须提问，禁止跳过。**
> 即使 category 可推断，只要研究目标不明确（如"分析一下X"只给了名称没说意图），就**必须先提问再规划**，不得直接进入 task_create。
> 典型必须澄清的输入："分析一下美的"、"研究下英伟达"、"看看茅台"、"帮我分析中芯国际" — 这类输入只给了标的名称，缺少研究意图和关注重点。

#### 层 1：research_category 识别（4 选 1）

判断用户问题属于以下哪一类（按"决策性质"归类，不按资产类别）：

| category       | 触发场景                                                               | 核心视角                                        | 输出形式                                                        |
| -------------- | ---------------------------------------------------------------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| **investment** | 标的投资研究（个股/债券/商品的买卖决策）"X 公司能不能买"、"深度研究 X" | 押注 — 赔率、目标空间、持有期、触发条件         | 押注表态（高确信看多/中性观察/高确信看空）+ 目标空间 + 范式标签 |
| **industry**   | 行业/赛道/主题/产业链研究 "研究 X 行业"、"X 赛道前景"                  | 格局 — 供需、竞争阶段、胜负手、产业演化         | 行业景气评级（高景气/中性/承压）+ 关键变量阈值 + 受益环节排序   |
| **macro**      | 宏观策略 / 利率 / 汇率 / 风格切换 "美联储降息节奏"、"信用周期判断"     | 路径 — 概率分布、关键节点、传导链、政策反应函数 | 基准路径 + 偏离场景 + 关键观测变量 + 概率分布                   |
| **event**      | 事件 / 政策 / 财报点评 / 暴雷分析 "解读 X 政策"、"X 公司暴雷影响"      | 传导链 — 直接 / 间接 / 二阶反馈                 | 影响等级 + 受益受损清单 + 时间线节奏                            |

**判断规则**：

- 跨类问题以"用户最终决策性质"为准。例：研究"AI 算力产业链中的英伟达" → 想押注买卖归 investment、想看产业格局归 industry
- 模糊不清不要硬猜——错误归类会让全套方法论错位（如把"宏观利率研判"当 investment 会强迫输出"目标空间 ±X%"）

#### 层 2：研究目标清晰度（同样重要，常被忽略）

即使 category 确定了，**研究目标本身**也必须清晰才能进 task_create。否则会做无用功（用户不知道想要什么 / 模型选错切入角度 / 报告写完用户说"这不是我想要的"）。

**模糊信号 — 按分类列出典型模糊输入，出现以下任一情况必须澄清**：

**investment 类模糊信号**：

- ❌ 只说了标的名称，没说研究意图（例："分析一下美的"、"研究下英伟达"、"看看茅台"、"帮我分析中芯国际" — 不知道是投资决策还是行业视角，**这是最常见的模糊输入，必须澄清**）
- ❌ 只给了行业没给具体标的（例："白酒哪只能买"、"新能源车选哪个" — 需用户给候选清单或同意先做 industry → 倒推个股）
- ❌ 没说关注重点（估值 / 成长性 / 困境反转 / 第二曲线 / 风险……至少锁定 1 个）

> **判断口诀：用户输入 ≤ 10 个字且只包含标的名称/行业名称 → 大概率模糊 → 必须提问。**

**industry 类模糊信号**：

- ❌ 研究对象过于宽泛（例："分析 AI 产业"、"研究医药"、"看看新能源" — 涉及多个细分赛道，需用户挑选）
- ❌ 没说关注重点维度（景气 / 格局 / 拐点 / 出海 / 龙头……至少锁定 1-2 个）
- ❌ 没说时间视角（短期 6 月内 / 中期 1-2 年 / 长期 3-5 年）

**macro 类模糊信号**：

- ❌ 只说了宏观主题，没说关注的具体路径（例："看下利率" — 是利率走势？降息节奏？收益率曲线？信用周期？）
- ❌ 没说空间范围（全球 / 美国 / 中国 / 欧洲 / 新兴市场 — 宏观变量跨市场差异大）
- ❌ 没说决策用途（资产配置 / 风险评估 / 政策预判 — 影响分析侧重）

**event 类模糊信号**：

- ❌ 没说哪一件具体事件（例："最近的政策影响" — 需明确哪个政策、生效时间）
- ❌ 说了事件但没说关注维度（对哪个行业/公司/资产的影响？还是整体市场影响？）
- ❌ 持续演进事件没说关注阶段（已发生部分解读？还是前瞻预判后续影响？）

**通用模糊信号（所有 category）**：

- ❌ 用户一句话输入且无法判断 category（例："研究下茅台" — investment? industry? event?）
- ❌ 跨类问题且用户没明确决策性质（例："AI 算力产业链中的英伟达" — investment 还是 industry？）

**清晰信号 — 出现以下任一情况可以直接进 task_create**：

- ✅ 用户已给详细 brief（对象 + 维度 + 时间都明确）
- ✅ 用户用了明确触发词（"快速解读今天的降准政策"已隐含 event + 短期 + 政策；"茅台能不能买"已隐含 investment）
- ✅ 仅 1 个维度模糊但对结论无关键影响（如时间视角不明可用默认中期，不打断）
- ✅ category 可从上下文明确推断（如用户在持仓讨论中提到某标的，显然是 investment）

#### 澄清话术规范

- 用一段简洁文本提问，**不超过 3 个问题**（多问会让用户烦）
- 优先级：**研究类型（category）> 研究对象 > 关注重点 > 时间视角**（类型不明时必须先问类型）
- 每个问题给 2-4 个候选项辅助用户决策（用户可选、可组合、可自定义）
- 用户回复后再走 Step 0b，**禁止"边问边创建任务"**

**澄清示例 — investment（用户输入"分析一下茅台"）**：

```
研究茅台之前需要先确认您的需求方向，不同方向的分析框架差异很大：

1. **您的研究意图是？**
   - 投资决策：茅台能不能买/卖？估值是否合理？（investment）
   - 行业视角：白酒行业格局与茅台的位置？（industry）
   - 事件解读：茅台最近出了什么具体事件？（event，需说明是哪个事件）

2. 如果是投资决策，**关注重点是什么？**
   - 当前估值是否合理
   - 第二曲线（系列酒 / 海外 / 直销占比提升）
   - 困境反转（如果近期下跌较多）
   - 长期护城河与复利空间

时间视角默认 1-3 年，如需调整请补充。
```

**澄清示例 — industry（用户输入"分析一下 AI 产业"）**：

```
研究 AI 产业之前需要先确认范围，避免分析方向偏离您的实际需求：

1. **聚焦哪条主线？**（可多选）
   - 算力基础设施（HBM / 光模块 / 液冷 / 服务器）
   - 大模型与应用（LLM / 多模态 / Agent）
   - AI 芯片（英伟达供应链 / 国产替代 / 寒武纪等）
   - AI 终端（PC / 手机 / 机器人）

2. **关注重点是什么？**
   - 行业景气与格局演化（哪条主线进入主升、CR5 演化）
   - 投资机会（具体标的的买点 / 估值）
   - 出海拓展（中国 AI 公司海外突破）
   - 风险点（监管 / 算力卡脖子 / 估值泡沫）

时间视角默认中期（1-2 年），如需调整请补充。
```

**澄清示例 — macro（用户输入"看下利率走势"）**：

```
利率研究范围较广，需要先聚焦您的关注点：

1. **具体关注哪方面？**
   - 美联储降息节奏与路径预判
   - 中国 LPR/MLF 走势与信用周期
   - 收益率曲线形态变化（倒挂/趋陡）
   - 全球利率联动与资本流动

2. **关注的空间范围？**
   - 美国
   - 中国
   - 全球/跨市场联动

3. **决策用途？**
   - 资产配置调整
   - 风险评估
   - 政策预判

时间视角默认中期（6-18 个月），如需调整请补充。
```

**澄清示例 — event（用户输入"最近的政策怎么看"）**：

```
需要先确认您关注的具体事件，"政策"范围太广无法聚焦：

1. **具体是哪个政策/事件？**
   - 货币政策（降准/降息/LPR 调整）
   - 行业监管（教培/互联网/房地产/医疗）
   - 财政政策（专项债/减税/补贴）
   - 贸易/地缘政治（关税/制裁/贸易协定）
   - 其他（请说明）

2. **您关注的影响维度？**
   - 对特定行业/公司的影响
   - 对整体市场/资产配置的影响
   - 对宏观环境（利率/汇率/信用）的影响

3. **关注的时间节奏？**
   - 即时冲击解读
   - 中期传导预判（1-6 月）
```

### Step 0b: 调 task_create（本 skill 特化要求）

**特化 1：必传 research_category 字段**

`task_create` 调用必须传入 `research_category`，取值范围严格限定为 `investment | industry | macro | event`，由 Step 0a 识别结果决定。这个字段决定下游 phase 文件的路由路径。

**特化 2：phases 描述必须针对性，禁止千篇一律，禁止使用内部流程术语**

phases 数量按 7 步主流程为骨架，可以合并/拆分但不要省略关键阶段。

**每个 phase 描述必须针对本次研究的核心问题定制**——让用户一眼看出"这一阶段会回答什么问题"，而不是流程标签。

**⚠️ 禁止在 phase 描述中使用内部方法论术语**（如"研究定界""信息扫描""假设生成""证据采集""量化分析""多空辩证""综合报告"）。这些术语是给模型内部路由用的，对用户毫无意义。phase 描述必须用**本次研究的具体内容**来写。

**反例（千篇一律 + 内部术语 — 禁止）**：

```
{ description: "研究定界 — 行业范围+子领域+四维维度" }
{ description: "信息扫描 — 按维度分派子模块并行采集" }
{ description: "假设生成 — 构建投资假设矩阵" }
```

**正例（针对性 + 用户语言）**：

```
研究"AI 算力赛道"：
{ description: "锁定 AI 算力产业链分段（HBM / 光模块 / 液冷 / 服务器整机），列出国内外可比标的清单" }
{ description: "扫描三条主线的渗透率、CR5、龙头资本开支，对标英伟达供应链与国内对标" }

研究"美联储降息节奏":
{ description: "确认本轮宏观周期定位（衰退/软着陆/再通胀），锁定关键观测变量（核心 PCE、非农、ISM）" }
{ description: "扫描期货市场降息预期、各 FOMC 委员立场、市场对'higher for longer'的当前定价" }

研究"美的集团投资价值"：
{ description: "确认美的的商业模式、竞争格局和核心关注点" }
{ description: "收集美的的财务数据、行业景气度和市场共识信息" }
```

## 路由表（phase → file 映射）

每个 phase 进入时，先 read 对应文件，再按文件规范执行。文件路径规则：

```
references/{research_category}/{phase-file}.md
```

| Phase | 文件名             | 说明（仅供模型内部组织思路，phase 描述里禁止使用这些名字） |
| ----- | ------------------ | ---------------------------------------------------------- |
| 1     | `01-scope.md`      | 研究定界                                                   |
| 2     | `02-scan.md`       | 信息扫描（多模块并行 subagent）                            |
| 3     | `03-hypothesis.md` | 假设生成（禁数据工具）                                     |
| 4     | `04-evidence.md`   | 证据采集（按假设并行 subagent）                            |
| 5     | `05-analyze.md`    | 量化分析 + 情景矩阵                                        |

| 7     | `07-synthesize.md` | 综合报告（+ 可选 PDF）                                     |

**辅助资料**：

## 7 步流程顺序

```
[Phase 0: 入口三步走] → 01-scope → 02-scan → 03-hypothesis → 04-evidence → 05-analyze → 06-challenge → 07-synthesize
                                                  ↑                              │
                                                  └──── 迭代返工（证据不足/致命缺陷）─┘
```

每一步的具体动作、产出、验收标准都在对应 phase 文件里详述。SKILL.md 不预判。

## 通用约束（4 类共享）

1. **双向采集**：证据必须同时收集支撑和反驳两个方向
2. **禁确认偏误**：不得先有结论再找证据，假设必须在数据扫描之后形成
3. **假设可证伪**：每个假设必须是可被数据支撑或反驳的具体命题
4. **认知差必覆盖**：每个 category 的假设矩阵中至少 1 个假设来自 D4（挑战市场共识）
5. **数据可追溯**：最终报告中所有数字和结论必须可追溯到具体的工具调用数据源（`[[p_xxxx]]` inline pid 标号）
6. **未覆盖场景**：当研究对象不属于 4 类标准时（如跨类研究、新型问题），按以下顺序处理：
   - 第一优先：尝试归入最接近的 category（绝大多数跨类问题都能找到主决策性质，如"AI 政策对芯片公司影响"以 event 为主、industry/investment 辅）
   - 第二优先：如果是明显的多 category 组合，主类承载输出形态，scan/evidence 阶段引用旁类方法论
   - 兜底：仍无法归类时，**停下来用 assistant 文本向用户说明**——告知当前 4 类的覆盖范围（investment/industry/macro/event）+ 询问"是否同意归入最接近的一类，或调整研究问题"。**禁止硬选一类闷头走 SOP**——错误归类会让全套方法论错位
7. **写入 md 文件 = 会话最终输出（字节级一致）**：用 Write 工具保存报告时，文件内容必须与本轮给用户的最终文本逐字符完全相同——禁止"剥离 inline pid 简化版写文件 + 完整版发用户"等编排转换
8. **对外禁用内部代号**：以下方法论代号是**给模型组织思路用的**，**禁止出现在面向用户的任何输出**（plan 大纲、phase 描述、task panel、最终报告）。对外必须翻译成人话：
   - `D1 / D2 / D3 / D4` → "商业本质 / 边际变化 / 市场共识 / 认知差"或更具体的章节名（如"产业本质"、"竞争格局"）
   - `H1 / H2 / H3` → 用一句话陈述假设本身，不带编号（如"渠道重构正在重塑盈利质量"，而非"H1: 渠道重构..."）
   - `bull / bear / neutral`、`bullish / bearish / structural` → "看好 / 看空 / 中性"或更精准的中文判断词
   - `optimistic / base / pessimistic` → "乐观 / 基准 / 悲观"或 category 自己的档位名（如"高景气 / 中性 / 承压"）
   - 内部 phase 名称（"研究定界"、"信息扫描"、"假设生成"、"证据采集"、"量化分析"、"多空辩证"、"综合报告"）→ **禁止出现在用户可见的任何地方**，包括 phase 描述、task 名称、plan 大纲。必须用**本次研究的具体内容**替代，例如"确认美的的商业模式和竞争格局"而非"研究定界"，"收集美的的财务数据和行业信息"而非"信息扫描"
   - 内部 phase 编号（如"Phase 3"、"01-scope"）→ 同上，禁止出现

## 迭代控制

- 阶段六 → 阶段四 之间最多迭代返工 **2 次**
- 迭代返工时通过阶段更新追加"补充证据"阶段
- 迭代返工只针对缺陷假设启动子模块，不重跑已充分的假设
- 超过迭代返工上限，强制进入阶段七，在报告中标注证据不足的假设

## 步骤调用规则

1. 读完 SKILL.md 后，**必须先完成 Phase 0 的三步**（识别 + plan + task_create），再进入 Phase 1
2. 进入每个 Phase 时，**必须先 read 对应的 reference 文档**（按路由表），然后按文档规范执行
3. **不要提前调用**后续阶段的研究模块（节省上下文）
4. 每个阶段完成后调用 task_update 完成阶段流转
5. 阶段二和阶段四通过子模块并行执行
6. **唯一禁令**：Phase 3（假设生成）禁止调用任何数据工具

## PDF 输出（可选增强交付）

最终报告支持一键渲染为专业 PDF。PDF 作为增强交付物，不替代 markdown 主报告。

**触发条件**：用户明确要求 PDF，或系统配置自动 PDF 输出。

**执行流程**（详细命令参数见 `shared/pdf-pipeline.md`）：

1. read `shared/pdf-pipeline.md` 了解完整命令和参数
2. read `shared/pdf-design-system.md` 了解设计系统决策
3. 运行桥接脚本 `scripts/research_to_content_json.py` 将 markdown + 图表数据 → `content.json`
4. 运行 `scripts/make.sh run` 生成封面 + 正文 + 合并 PDF

**设计调性速查**：金融研报默认 `--type report --accent "#1C3A5E"`；TMT/科技类研究 `--type darkroom --accent "#4A6FA5"`；正式出版物用 `--type magazine`。
