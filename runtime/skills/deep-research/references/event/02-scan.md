# 02 - 信息扫描（event · 多模块并行 subagent）

## 角色

信息扫描负责人 — 按 event 四维维度分派子模块聚焦采集事件相关数据，只记录不判断。

## 输入交付物

事件研究任务书（来自 Phase 1）

## 执行模式

**多模块并行** — 按维度启动独立子模块，每个子模块负责一个维度的数据采集。

> event 研究的扫描比 investment/industry 更聚焦：事件研究时效性强，子模块数量可精简为 3-4 个（lite 档位时 3 个即可），采集窗口更短。

## SOP

### Step 1: 构造子模块任务

读取事件研究任务书中的四维分析维度、直接影响范围、历史类比，为每个维度构造子模块任务描述。

### Step 2: 启动子模块

为以下维度各启动一个子模块（**注意每个子模块都是事件传导视角，不是单股/行业全景**）：

---

**子模块一（事件事实与直接影响扫描）**：

```
你是信息扫描专家，负责采集 {event_subject} 的事件事实和直接影响数据。
调查方向：{4d_dimensions.D1}

采集内容：
- 事件核心内容（政策原文/财报数据/公告原文的关键条款）
- 事件生效时间和执行细节
- 直接受影响的行业/公司清单（第一层，5-15 家代表标的）
- 直接受影响资产的价格反应（事件后 1 日/1 周/1 月）
- 相关方的官方回应/解读
- 市场即期反应（成交量、波动率、资金流向）

要求：聚焦事件本身和第一层影响，不展开间接传导。只记录数据不做分析判断。
禁止：不得再 spawn 子 agent，所有工具调用必须由你自己直接执行。
输出：按影响维度分组的数据摘要，含数据时间戳和来源。
```

---

**子模块二（传导链与间接影响扫描）**：

```
你是信息扫描专家，负责采集 {event_subject} 的传导链数据。
调查方向：{4d_dimensions.D2}

采集内容：
- 间接传导路径（供应商/客户/替代品/互补品受影响情况）
- 二阶反馈信号（市场情绪变化、资金跨市场流动、风险偏好切换）
- 各层传导的时滞估计（即时/1-3 月/3-12 月）
- 历史类比事件中类似传导链的实际表现
- 跨市场影响（股/债/汇/商品/衍生品是否联动）

要求：聚焦"传导"和"时滞"，记录事实不做判断。所有事件标注时间戳。
禁止：不得再 spawn 子 agent。
输出：按传导层级（直接 → 间接 → 二阶）排列的数据和事件。
```

---

**子模块三（市场定价与认知扫描）**：

```
你是信息扫描专家，负责采集 {event_subject} 的市场定价和认知数据。
调查方向：{4d_dimensions.D3 + D4}

采集内容：
- 卖方/买方对该事件的即时解读（评级调整/目标价调整/配置建议变化）
- 期权市场隐含波动率变化（如有）
- 资金流向（北向/南向/主力/融资融券在事件前后的变化）
- 媒体/社交平台情绪指标（舆情热度、高频叙事词）
- 历史类比事件中市场定价的偏差和修正过程

要求：客观记录市场观点和定价数据，不做自己的判断。
禁止：不得再 spawn 子 agent。
输出：市场定价方向总结 + 关键数据点 + 主流叙事词列表。
```

---

**子模块四（历史类比扫描）**（full 档位时启动，lite 档位可跳过）：

```
你是历史研究专家，负责为 {event_subject} 采集历史类比事件数据。
执行档位：{event_depth_tier}

按档位采集：

| 档位 | 采集内容 | 输出下限 |
|------|---------|---------|
| full | 【1】2-3 个国内外类似事件的完整复盘（每个 ≥500 字，含事件背景、市场即时反应、后续 1/3/6/12 月演化、传导链实际表现、市场定价偏差）<br>【2】2-3 个事件范式案例（每个 ≥200 字），来自 paradigms.md（黑天鹅/灰犀牛/政策红利/政策收紧/传染链等）<br>【3】本次事件与历史类比的异同点对照 | 2000 字 |
| lite | 【1】1-2 个类似事件简述（每个 ≥300 字）<br>【2】1-2 个事件范式案例（每个 ≥150 字）<br>【3】简要异同对照 | 800 字 |

通用要求：
- 引用具体事件名、日期、数据，禁止"历史上类似事件表明..."这种空话
- 类比要找"事件性质 + 传导机制相似"，不是简单同行业
- 原料确实不存在时必须显式声明缺失原因，禁止编造
- 数据可来自财经数据库、公开研报、新闻档案等

禁止：不得再 spawn 子 agent。
输出：按【1】【2】【3】分组，开头标注本次实际执行档位。
```

### Step 3: 汇总 ScanFindings

收齐所有子模块的提交结果后，将各维度数据摘要汇总为信息采集底稿。不做分析，只做结构化整理。

## 数据文件传递

子模块内工具调用产生的数据文件由系统自动持久化。子模块向主模块汇报时，系统自动汇总数据文件路径、字段结构和 exec 调用模板。后续阶段五可直接通过 exec 调用这些文件做定量计算。

## 产出交付物：事件信息采集底稿

```
## D1 事件事实与直接影响
{子模块一的数据摘要}

## D2 传导链与间接影响
{子模块二的数据摘要 — 按传导层级排列}

## D3/D4 市场定价与认知
{子模块三的数据摘要 — 含市场定价程度和主流叙事}

## 历史类比
执行档位：{full | lite}
{按档位输出对应内容；lite 时子模块四可省略}

## 数据文件引用
{系统自动拼接的数据文件路径列表}
```

## 阶段验收标准

- 子模块一和子模块二已提交结果（必选）
- 子模块三已提交结果（必选）
- D1 事件核心事实已确认（核心内容/生效时间/直接影响范围）
- D2 至少覆盖直接传导 + 1 层间接传导
- 历史类比模块按档位达标：
  - tier=full：三件事均有实质输出，总字数 ≥ 2000 字
  - tier=lite：两件事均有实质输出，总字数 ≥ 800 字（或子模块四省略，由 03-hypothesis 阶段简要参照）
- 满足后完成本阶段并进入阶段三

## 关键差异提示（vs investment / industry）

- **子模块数量更少**（3-4 个 vs investment/industry 的 5 个）：事件研究时效性强，不需要"宏观与对标"独立子模块（传导链已含宏观影响），历史类比可降档
- **D2 子模块最关键**：传导链是 event 研究的核心，采集深度决定报告质量
- **时间窗口更短**：事件数据聚焦近期（近 1-3 个月为主），不需要 5-10 年历史纵深
- **lite 档位更轻量**：lite 档可跳过历史类比子模块，由 03-hypothesis 阶段简要参照范式库
